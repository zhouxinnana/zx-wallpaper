一个需求如何穿过全栈系统

你不需要先学完 Java 才能理解全栈。先抓住一件事：每层都有它负责的决策，AI 生成的代码也必须服从这些边界。

场景

为壁纸应用增加“收藏壁纸”功能。用户点收藏，页面立即更新；服务端记录当前用户与壁纸的关系；重复收藏不能产生两条记录。

Vue button → POST /api/wallpapers/{id}/favorite → FavoriteService → FavoriteRepository → database

每层要回答的问题

Vue：按钮何时可点？请求期间怎么显示？失败如何回滚或提示？

Controller：这个 HTTP 请求是否合法？当前用户是谁？返回什么状态码和 JSON？

Service：该用户是否能收藏？已经收藏时如何处理？这一步需要原子完成吗？

Repository / database：如何读取和保存收藏关系？如何用唯一约束保证不重复？

这里的关键是：规则的最终裁决在服务端。前端校验为了体验，后端校验为了正确性和安全性。

检索练习

“同一用户不能重复收藏同一壁纸”这条规则，最终应由哪一层保证？

一分钟拆分

不写代码，试着回答：若收藏请求失败，Vue 应做什么？Service 应做什么？数据库应做什么？用自己的话发给我，我会按边界给你反馈。

下一节会把这条路径落实为一个最小 Spring Boot API：Controller、Service、Repository 各写什么，哪些东西暂时不写。
